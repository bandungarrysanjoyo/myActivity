2. Apa itu Dynamic Programming?

Definisi

Dynamic Programming adalah teknik untuk menyelesaikan sebuah kelompok masalah tertentu dengan memecahnya menjadi sub-masalah yang lebih kecil, menyelesaikan setiap sub-masalah hanya satu kali, lalu menyimpan hasilnya untuk dipakai kembali.

Tiga hal yang ditekankan:

a) DP bukan obat untuk semua masalah

DP hanya berlaku untuk masalah yang punya sifat-sifat tertentu (dibahas di bagian 3). Teknik ini digunakan luas di dunia nyata: matematika, bioinformatika, teori permainan, ekonomi, statistik, linguistik, dan ilmu komputer (misalnya: diff/algoritma perbandingan teks, rute terpendek di peta, pengenalan suara).

b) Kekuatan utama DP: memangkas waktu ekspansial → polinomial

Sebuah solusi naif (brute force / rekursi mentah) sering berjalan dalam waktu eksponensial — misalnya O(2ⁿ), yang untuk n = 50 sudah miliaran-triliunan langkah. DP memangkasnya menjadi waktu polinomial seperti O(n²) atau O(n·k), bahkan kadang linear O(n):

Artinya DP pada hakikatnya adalah teknik optimasi: mengoptimalkan solusi yang benar menjadi solusi yang cepat.

c) Model “kotak hitam”

Cara paling sederhana memandang DP: sebuah kotak hitam yang menerima deskripsi masalah sebagai input dan mengeluarkan solusi. Di dalam kotak itu terjadi: pecah masalah → selesaikan sub-masalah terkecil → bangun naik ke atas dengan memanfaatkan hasil yang sudah ada.

3. Dua Sifat Wajib Masalah DP

Masalah bisa diselesaikan dengan DP ⟺ memiliki kedua sifat ini.

① Optimal Substructure

Optimal = terbaik. Substructure = sub-masalah dari masalah utama.

Definisi

Sebuah masalah memiliki optimal substructure jika solusi optimal masalah utama dapat dibangun dari solusi optimal sub-masalahnya.

Ilustrasi: untuk masalah besar yang dipecah jadi X₁, X₂, X₃, …:

  • Selesaikan X₁ secara optimal.
  • Gunakan hasil X₁ untuk mendapatkan solusi optimal X₂ — tanpa menghitung ulang dari awal.
  • Begitu seterusnya sampai Xₙ = masalah utama terjawab optimal.

② Overlapping Subproblems

Saat masalah dipecah, sub-masalah yang sama muncul berulang kali dan tanpa DP kita akan menghitungnya berulang-ulang.

Definisi

Jika sub-masalah yang sama perlu diselesaikan lebih dari sekali, masalah memiliki overlapping subproblems — kandidat kuat untuk DP.

Contoh klasik: pohon rekursi Fibonacci fib(5) di bawah. Perhatikan fib(3) dihitung 2×, fib(2) dihitung 3×, fib(1) bahkan 5×.

💡 Kesimpulan bagian ini: kalau pohon rekursi kita “menggembang” karena banyak simpul yang sama dihitung berulang → simpan hasilnya sekali saja (cache). Trik penyimpanan hasil ini disebut memoization, dan masalahnya jadi cocok untuk DP.

5. Kerangka Kerja (Framework) Menyelesaikan Soal DP

Ini pola baku yang dipakai:

  1.  Tentukan fungsi tujuan (objective function)

Rumuskan apa yang dihitung f(i), lengkap dengan deskripsinya dalam kata-kata. Menurut Andrey, langkah ini sudah

~50% dari solusi

— deskripsinya hampir selalu tersirat di soal. Contoh: “f(i) = banyaknya cara berbeda mencapai anak tangga ke-i”.

  1.  Tentukan base case (kasus dasar)

Selesaikan masalah untuk input sekecil mungkin — sekecil itu sampai “tidak perlu komputer”. Base case membatasi ruang masalah dan menghentikan rekursi. Contoh: f(0) = 1 (cara “berdiri di tanah”), f(1) = 1.

  1.  Rumuskan relasi rekuren (transition function)

Hubungkan f(i) dengan sub-masalah yang lebih kecil, mis. f(i) = f(i−1) + f(i−2). Asumsikan sub-masalah sudah terjawab.

  1.  Tentukan urutan perhitungan (bottom-up) atau memo (top-down)

Hitung dari base case menuju jawaban, simpan tiap hasil di array dp[] agar tidak dihitung ulang — inilah

memoization

: trade-off memori demi kecepatan (time–memory trade-off).

  1.  Tentukan lokasi jawaban

Jawaban akhir biasanya di dp[n] (elemen terakhir), tapi bisa juga min(dp[n−1], dp[n−2]) dsb. — selalu cek kembali definisi f.

  1.  (Opsional) Rekonstruksi solusi

Jika yang diminta bukan hanya angka, tapi langkah-langkahnya (koin mana yang dipakai, jalur mana yang ditempuh), simpan “jejak”/predecessor lalu telusuri mundur (video 08).

📌 Memoization dalam satu kalimat (kutipan inti video 04): “Kita tidak ingin menghitung ulang hal-hal; kita ingin bergantung pada solusi yang sudah ada.” — tahu f(5) = 15, maka f(6) cukup 15 + 6 = 21, tanpa mengulang dari awal.

6. Contoh 1 — Jumlah Bilangan 1 sampai n (Soal Elementer)

Sengaja dipakai soal super sederhana agar “terasa” mekanisme DP-nya. (Jelas permasalahan ini dapat dijawab rumus deret aritmetika, tapi abaikan itu dulu!)

Masalah: hitung S(n) = 1 + 2 + 3 + … + n (simbol Σ itu “for loop”-nya matematika).

Terapkan framework:

  • Objective function: f(i) = jumlah bilangan dari 1 sampai i.
  • Base case: f(0) = 0 (tidak ada yang dijumlahkan), f(1) = 1.
  • Relasi rekuren: f(i) = f(i−1) + i — jumlah sampai i-1, ditambah elemen ke-i.

// dp[i] = 1 + 2 + ... + i

static int sumToN(int n) {

    int[] dp = new int[n + 1];

    for (int i = 1; i <= n; i++) {

        dp[i] = dp[i - 1] + i;      // relasi rekuren: f(i) = f(i-1) + i

    }

    return dp[n];

}

sumToN(5)   // → 15

7. Contoh 2 — Climbing Stairs (Naik Tangga)

Masalah: ada tangga dengan n anak tangga. Setiap langkah kamu boleh naik 1 atau 2 anak tangga. Berapa banyak cara berbeda mencapai puncak?

Contoh n = 4 → ada 5 cara:

1+1+1+11+1+21+2+12+1+12+2

Terapkan framework:

  • Objective function: f(i) = banyaknya cara berbeda mencapai anak tangga ke-i.
  • Base case: f(0) = 1 (satu “cara”: berdiri di tanah / tidak melangkah), f(1) = 1 (hanya satu langkah kecil).
  • Relasi rekuren: ke tangga ke-i kamu hanya bisa datang dari i−1 (langkah 1) atau i−2 (lompatan 2). Maka f(i) = f(i−1) + f(i−2) — pola Fibonacci!
  • Jawaban: dp[n].

static int climbingStairs(int n) {

    int[] dp = new int[n + 1];

    dp[0] = 1;                          // base case: berdiri di tanah

    dp[1] = 1;                          // base case: tangga ke-1

    for (int i = 2; i <= n; i++) {

        dp[i] = dp[i - 1] + dp[i - 2];  // dari i-1 (langkah 1) atau i-2 (lompatan 2)

    }

    return dp[n];

}

 

// pemanggilan:

climbingStairs(4)   // → 5

⏱️ Perbandingan kompleksitas (lihat video 11): rekursi naif = O(2ⁿ) — untuk n=40 butuh ± 2³⁷ pemanggilan; dengan DP bottom-up = O(n) waktu, O(n) memori (bisa dioptimalkan jadi O(1) memori karena hanya butuh dua nilai sebelumnya).

8. Contoh 3 — Tangga dengan Anak Tangga Merah

Masalah: sama dengan sebelumnya (naik 1 atau 2 langkah), tapi beberapa anak tangga berwarna merah dan tidak boleh diinjak. Berapa banyak cara mencapai puncak?

Perubahan minimal pada solusi: jumlah cara menuju tangga merah = 0, dan tangga merah tidak bisa menjadi “batu loncatan”. Cukup tambahkan pengecekan di dalam loop:

if (red[i]) {

} else {

    dp[i] = dp[i - 1] + (i >= 2 ? dp[i - 2] : 0);   // tangga biasa

}

static int redStairs(int n, boolean[] red) {

    int[] dp = new int[n + 1];

    dp[0] = 1;

    for (int i = 1; i <= n; i++) {

        if (red[i]) {

            dp[i] = 0;                                  // tangga merah

        } else {

            dp[i] = dp[i - 1] + (i >= 2 ? dp[i - 2] : 0);

        }

    }

    return dp[n];

}

9. Contoh 4 — Masalah Optimasi & Rekonstruksi Solusi

Masalah (Min Cost Climbing Stairs): setiap anak tangga ke-i punya biaya cost[i] yang harus dibayar saat menginjaknya. Kamu mulai dari bawah, boleh naik 1 atau 2 langkah, dan tujuannya puncak (di atas tangga terakhir). Berapa biaya total minimum?

Framework:

  • Objective function: f(i) = biaya minimum untuk mencapai dan menginjak tangga ke-i.
  • Base case: f(0) = cost[0], f(1) = cost[1].
  • Relasi rekuren: f(i) = cost[i] + min(f(i−1), f(i−2)) — inilah wajah khas masalah optimasi: fungsi tujuan memakai min.
  • Jawaban: min(f(n−1), f(n−2)) — dari dua tangga terakhir kita boleh melompat langsung ke puncak.

Contoh: cost = [10, 15, 20]

Jawaban = min(15, 30) = 15 (mulai dari tangga 1, lalu lompat 2 langkah ke puncak).

static int[] dp, parent;    // parent[] untuk rekonstruksi (video 08)

 

static void solveMinCostStairs(int[] cost) {

    int n = cost.length;

    dp = new int[n];

    parent = new int[n];

    java.util.Arrays.fill(parent, -1);

    dp[0] = cost[0];

    dp[1] = cost[1];

    for (int i = 2; i < n; i++) {

        if (dp[i - 1] <= dp[i - 2]) {       // pilih predecessor yang lebih murah,

            dp[i] = cost[i] + dp[i - 1];    // catat jejaknya

            parent[i] = i - 1;

        } else {

            dp[i] = cost[i] + dp[i - 2];

            parent[i] = i - 2;

        }

    }

}

 

// telusuri mundur dari jawaban → rekonstruksi langkah-langkahnya

static java.util.List<Integer> reconstruct(int best) {

    java.util.List<Integer> path = new java.util.ArrayList<>();

    for (int i = best; i != -1; i = parent[i]) path.add(i);

    java.util.Collections.reverse(path);

    return path;

}

 

// pemanggilan:

solveMinCostStairs(new int[]{10, 15, 20});

int best = (dp[2] <= dp[1]) ? 2 : 1;        // jawaban: min(f(n-1), f(n-2))

best            // → 1  (tangga tempat mulai melompat ke puncak)

dp[best]        // → 15  (biaya minimum)

reconstruct(best)  // → [1]  (jalur: injak tangga 1, lalu lompat ke puncak)

10. Contoh 5 — Unique Paths (DP Dua Dimensi)

Masalah: sebuah robot berada di pojok kiri-atas grid m × n. Robot hanya boleh bergerak ke kanan atau ke bawah. Berapa banyak jalur berbeda menuju pojok kanan-bawah?

Framework:

  • Objective function: f(i, j) = banyaknya jalur berbeda mencapai sel baris-i, kolom-j.
  • Base case: seluruh baris pertama dan kolom pertama bernilai 1 (hanya ada satu cara: lurus terus).
  • Relasi rekuren: ke sel (i, j) hanya bisa datang dari atas atau dari kiri → f(i, j) = f(i−1, j) + f(i, j−1).
  • Jawaban: dp[m−1][n−1] (kanan bawah).

static int uniquePaths(int m, int n) {

    int[][] dp = new int[m][n];

    for (int[] row : dp)

        java.util.Arrays.fill(row, 1);          // base case: baris & kolom pertama = 1

    for (int i = 1; i < m; i++) {

        for (int j = 1; j < n; j++) {

            dp[i][j] = dp[i - 1][j] + dp[i][j - 1];   // dari atas + dari kiri

        }

    }

    return dp[m - 1][n - 1];

}

 

// pemanggilan:

uniquePaths(3, 4)   // → 10

Struktur solusinya persis sama dengan soal 1-dimensi — objective function, base case, relasi rekuren, urutan iterasi. Yang berubah hanyalah dimensi tabel (state kini (i, j)): array int[][] dan dua loop bersarang. Kalau suatu saat ada parameter ketiga (misal “maksimal k belokan”), tabel pun bertambah satu dimensi.

11. Contoh 6 — Top-Down vs Bottom-Up

Dua gaya menulis solusi DP untuk masalah yang sama.

🔽 Top-Down (Memoization)

Mulai dari masalah besar (f(n)), “turun” lewat rekursi, dan simpan hasil tiap sub-masalah di cache saat pertama kali dihitung. Mirip solusi naif + array cache.

static long[] memo = new long[100];

 

static long fibTopDown(int n) {

    if (n <= 1) return n;           // base case

    if (memo[n] != 0)

        return memo[n];             // sudah pernah dihitung

    memo[n] = fibTopDown(n - 1)

            + fibTopDown(n - 2);

    return memo[n];

}

✅ plus: alamiah, sesuai relasi rekuren, hanya menghitung state yang benar-benar dibutuhkan.
⛔ minus: overhead rekursi (call stack), risiko StackOverflowError untuk n besar.

🔼 Bottom-Up (Tabulation)

Mulai dari base case, isi tabel dari kecil ke besar sampai jawaban. Tidak ada rekursi sama sekali.

static long fibBottomUp(int n) {

    if (n <= 1) return n;

    long[] dp = new long[n + 1];

    dp[1] = 1;                      // base case

    for (int i = 2; i <= n; i++) {

        dp[i] = dp[i - 1] + dp[i - 2];

    }

    return dp[n];

}

✅ plus: cepat, tanpa overhead rekursi, mudah dioptimalkan memori.
⛔ minus: bisa menghitung state yang tidak diperlukan; urutan iterasi harus benar.

⚖️ Keduanya ekuivalen: kompleksitas waktunya sama O(n) — fibTopDown(10) maupun fibBottomUp(10) menghasilkan 55. Gaya bottom-up biasanya dipilih untuk solusi final; top-down enak dipakai saat “berpikir”. Mayoritas contoh ditulis bottom-up, tapi konsepnya sama persis.

Contoh perhitungan dp[6]: pilih koin 3 → 1 + dp[3] = 2 ✓ (lebih baik daripada koin 1 → 1+dp[5]=3, atau koin 4 → 1+dp[2]=3). Jawaban: 2 koin → 3 + 3.

static int coinChangeMin(int[] coins, int amount) {

    final int INF = Integer.MAX_VALUE - 1;

    int[] dp = new int[amount + 1];

    java.util.Arrays.fill(dp, INF);

    dp[0] = 0;                          // dp[0] = 0: jumlah 0 butuh 0 koin

    for (int i = 1; i <= amount; i++) {

        for (int c : coins) {

            if (c <= i && dp[i - c] + 1 < dp[i]) {

                dp[i] = dp[i - c] + 1;  // pakai koin c, +1 hitungannya

            }

        }

    }

    return dp[amount] >= INF ? -1 : dp[amount];   // -1 = tidak mungkin

}

static int coinChangeWays(int[] coins, int amount) {

    int[] dp = new int[amount + 1];

    dp[0] = 1;                      // satu cara membentuk 0: tanpa koin sama sekali

    for (int c : coins) {           // koin di LUAR — urutan koin tidak dihitung

        for (int i = c; i <= amount; i++) {

            dp[i] += dp[i - c];

        }

    }

    return dp[amount];

}

coinChangeWays(new int[]{1, 2, 5}, 5)   // → 4

13. Contoh 8 — Shortest Path in DAG 

Video penutup membawa DP ke dunia graf: mencari jalur terpendek pada DAG (Directed Acyclic Graph — graf berarah tanpa siklus). Titik-titik (kota) dihubungkan sisi berbobot (waktu/jarak), dan kita mencari jalur termurah dari A ke F.

Masalahnya: pada graf tidak ada “urutan alami” seperti indeks 0,1,2,…,n. Trik-nya: ciptakan urutan terlebih dahulu dengan topological sorting (toposort). Setelah simpul diuraskan sehingga setiap sisi menunjuk ke depan, relasi rekuren DP biasa berlaku:

// dp[v] = biaya minimum mencapai simpul v (Infinity di awal, dp[start] = 0)

// setelah toposort, proses simpul u satu per satu sesuai urutan:

for (Edge e : adj[u]) {                 // tiap sisi u → v dengan bobot e.w

    dp[e.v] = Math.min(dp[e.v], dp[u] + e.w);

}

Pelajarannya: DP tidak selalu soal array dari 0..n — DP bekerja pada struktur apa pun yang bisa dibuat “tanpa siklus” dan berurutan (DAG adalah habitat alami DP; bahkan tabel DP kita selama ini secara implisit adalah DAG dari sub-masalah!).


14. Ringkasan & Tips Praktis

Ringkasan sekali baca

  • DP = pecah → hitung sekali → simpan → pakai ulang. Teknik optimasi dari solusi eksponensial ke polinomial.
  • Syarat masalah: optimal substructure + overlapping subproblems.
  • Type permasalahan: “berapa banyak cara” (kombinatorik) atau “min/max” (optimasi).
  • Memoization = menyimpan hasil perhitungan agar bisa dipakai ulang; trade-off memori demi waktu.
  • Top-down (rekursi + cache) dan bottom-up (tabel) menghasilkan kompleksitas yang sama.
  • Perlu langkah solusinya? Simpan predecessor dan telusuri mundur.
  • DP hidup di dunia DAG: struktur sub-masalah harus tidak punya siklus (pun urutan yang jelas — pada graf, dibuat lewat toposort).
